# Використання LLM під час розробки (розділ 2 завдання)

## Модель і harness

Для проєктування й верстки використовувалась модель **Claude Opus 5.5** (Anthropic) в агентному середовищі **Claude Code**, розширенні для VS Code. Claude Code працює безпосередньо з локальним репозиторієм: читає й редагує файли, запускає команди `flutter analyze`, `flutter test`, `flutter build ios`, `xcrun simctl` і робить git-коміти. Через протокол MCP (Model Context Protocol) до агента було підключено **сервер Figma MCP**, який дає моделі доступ до макетів ЛР №2. Використано інструменти `get_metadata` (структура сторінки й розміри фреймів), `get_variable_defs` (змінні дизайну), `get_design_context` (структура вузла з точними розмірами, кольорами, шрифтами й посиланнями на ассети), `get_screenshot` (еталонне зображення фрейму) та `use_figma` (домальовування відсутніх екранів Forgot Password і Change Password з наявних шарів макета).

## Робочий процес

Вхідними даними були специфікація вимог із ЛР №2 (функціональні вимоги FR1–FR11, нефункціональні NFR1–NFR7, правила Apple HIG) і посилання на фрейми Figma. Спочатку агент провів розвідку макета: зібрав і дедуплікував токени (кольори, типографіку, відступи, тіні), знайшов розбіжності між екранами та відсутні екрани. За результатами він сформував план, який я затвердив, і поставив питання щодо неоднозначностей. Далі розробка йшла фазами: фундамент проєкту (тема, ассети, моделі, маршрутизація) → перевикористовувані віджети `core/widgets` → екрани по одному → етап 2. Кожен екран після верстки знімався на симуляторі iPhone 17e і порівнювався з рендером фрейму Figma поруч (`docs/compare/`), а позиції елементів вимірювались по пікселях. Розбіжності виправлялись, рішення фіксувались у `docs/decisions.md`. Перед кожним комітом запускались `flutter analyze` і widget-тести, зокрема перевірка відсутності overflow на iPhone SE та 17 Pro Max.

## Приклад запиту до LLM (скорочено)

> Ти — senior Flutter-розробник із досвідом pixel-perfect верстки з Figma. Виконую ЛР №3: створити базову структуру Flutter-застосунку PlacesCatalog і pixel-perfect реалізувати основні екрани за дизайном із ЛР №2 **без бізнес-логіки** (hardcoded/mock-дані, кнопки просто ведуть на наступний екран).
>
> Потрібно зверстати: реєстрацію та авторизацію з відновленням пароля через email; профіль зі зміною пароля; головний екран. Перевикористовувані віджети — у `lib/core/widgets`. Цільова платформа — iOS 14+ за Apple HIG: нижній Tab Bar Home / Favorites / Profile, без Drawer і FAB, свайп назад, деструктивні дії через `CupertinoAlertDialog`, зона натискання ≥ 44 pt, Safe Area.
>
> Обмеження: без state-management бібліотек, Firebase чи HTTP; стан через `StatefulWidget` + `setState`; навігація — `Navigator` з named routes і `CupertinoPageRoute`. Посилання на фрейми Figma: Login — `…?node-id=1-902`, Create Account — `…?node-id=9-24`, Home — `…?node-id=1-70`, Profile — `…?node-id=1-496`.
>
> Робочий процес: спочатку розвідка макета через Figma MCP і план на затвердження (токени, віджети, мапа «екран → віджети», відкриті питання); потім фундамент, віджети й екрани по одному. Кожен екран порівнюй зі скриншотом Figma на тому самому логічному розмірі й комміть окремо.
